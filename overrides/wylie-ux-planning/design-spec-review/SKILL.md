# Design Spec Review

## 입력

- 기준 화면설계서 또는 승인된 명세
- Figma URL, export 이미지, 또는 프로토타입
- 검토 범위와 출력 위치

## 원칙

- 기준은 승인된 명세, 검수 대상은 디자인 시안이다.
- 명세 자체의 결함은 별도 내부 항목으로 분리한다.
- 근거 없는 이슈를 만들지 않는다.
- 화면명과 기능으로 매칭하며 번호만 믿지 않는다.

## 절차

1. 기준 파일의 버전, 페이지/슬라이드 수, 해시를 기록한다.
2. 시안은 가능한 경우 공식 export 기능으로 PNG/PDF를 받는다. 자동화가 없으면 사용자가 내보낸 파일을 사용한다.
3. 큰 이미지는 사용 가능한 이미지 도구로 화면 단위 분할한다. 특정 OS 전용 도구를 강제하지 않는다.
4. 명세의 텍스트, 표, 그룹, 주석을 읽기 전용으로 추출한다.
5. 화면별로 라벨, 버튼, 상태, 흐름, 접근성, 공통 컴포넌트를 비교한다.
6. `[일치]`, `[시안에 없음]`, `[시안과 다름]`, `[시안에만 있음]`, `[판독 어려움]`으로 판정한다.
7. 실제 전달 항목은 `수정 요청`과 `확인 요청`으로만 정리한다.

## Figma 댓글

댓글 검토는 선택 기능이다. 공개 API, 공식 export, 사용자가 제공한 댓글 목록을 우선한다. 비공개 내부 엔드포인트·세션 쿠키·토큰을 저장하거나 배포하지 않는다. 댓글 접근이 불가하면 디자인 정합성 검토와 분리해 `미확인`으로 남긴다.

## 산출물

- `design-review-report.html` 또는 `.md`
- 필요 시 화면별 비교 이미지
- 반복 검토 시 `review-ledger.json`

리포트에는 기준 문서명·버전, 화면명, 명세 페이지, 디자인 위치, 요청 문구, 잘 반영된 부분을 포함한다. 도구명·에이전트명·개인 경로는 노출하지 않는다.

## 완료 조건

- 기준과 대상 방향이 뒤집히지 않음
- 모든 요청에 명세 페이지 또는 근거 문구 있음
- 공통 컴포넌트를 누락으로 오판하지 않음
- 비밀값·쿠키·비공개 API 데이터 없음
