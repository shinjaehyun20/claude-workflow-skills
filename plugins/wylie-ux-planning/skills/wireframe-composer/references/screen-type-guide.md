# 화면 유형별 구성 원칙 가이드

## TYPE-A: 대시보드형

**목적**: 여러 정보 요약 + 주요 기능 CTA 진입점 제공
**대표 화면**: 메인 홈, 마이페이지 홈

### 레이아웃 원칙
- 히어로 영역 (Hero): 가장 중요한 상태/CTA 배치
- 퀵 링크 영역: 자주 쓰는 기능 4~8개, 아이콘 + 텍스트
- 정보 카드 영역: 최신 공지, 시험 일정, 합격 결과 등
- 하단: 관련 링크, 공지사항 전체보기

### PC 구조 (1280px)
```
[히어로 영역 - 전체 너비, 상태별 전환]
[퀵 링크 4~6개 - 가로 배열]
[2~3단 카드 그리드]
  [왼쪽: 공지/소식]  [오른쪽: 일정/결과]
[관련 사이트 링크]
```

### MO 구조 (360px)
```
[히어로 영역 - 전체 너비]
[퀵 링크 2×N 그리드]
[카드 단일 컬럼 스택]
[관련 링크]
```

### 상태 변형 처리
- 히어로만 상태별 교체 (나머지 공통)
- 상태: 상시 / 접수전(D-N) / 접수기간 (CTA 강조)

### 주요 KRDS 컴포넌트
- Card, Button (Primary CTA), Badge (상태 표시), Carousel (선택)

## TYPE-B: 목록형

**목적**: 데이터 목록 탐색 + 검색/필터
**대표 화면**: 공지사항, 시험 일정 목록, 합격자 발표 목록

### 레이아웃 원칙
- 상단: 페이지 제목 + 브레드크럼
- 검색/필터 영역: 주요 필터 3개 이내 (더 많으면 접기)
- 목록 영역: 테이블 또는 카드 목록
- 하단: 페이지네이션

### PC 구조
```
[브레드크럼]
[페이지 제목]
[검색 바 + 필터 (접기/펼치기)]
[목록 테이블]
  [체크박스] [번호] [제목] [날짜] [조회수]
[페이지네이션]
```

### MO 구조
```
[페이지 제목]
[검색 + 필터 아이콘]
[카드형 목록 (테이블→카드 전환)]
[페이지네이션]
```

### 주의사항
- 테이블은 MO에서 카드형으로 전환
- 체크박스 + 일괄 작업 버튼 (관리형 목록만)
- 빈 결과 상태(Empty State) 반드시 설계

### 주요 KRDS 컴포넌트
- Table, Pagination, Input (검색), Select (필터), Badge

## TYPE-C: 상세형

**목적**: 단일 항목의 상세 정보 표시
**대표 화면**: 공지사항 상세, 합격자 발표 상세, 시험 정보 상세

### 레이아웃 원칙
- 상단: 브레드크럼 + 제목 + 메타 정보 (날짜, 카테고리)
- 본문: 콘텐츠 영역 (최대 너비 제한)
- 하단: 첨부 파일 목록 + 이전/다음 네비게이션 + 목록으로 버튼

### PC 구조
```
[브레드크럼]
[제목 / 작성일 / 조회수]
[구분선]
[본문 콘텐츠]
[첨부 파일 목록]
[구분선]
[이전글] [목록] [다음글]
```

### MO 구조
```
[브레드크럼 (단축형)]
[제목 / 메타]
[본문 (전체 너비)]
[첨부 파일]
[목록 버튼]
```

### 주의사항
- 본문 폰트: 최소 16px, 줄간격 1.6 이상
- 이미지: 반응형 (max-width: 100%)
- 인쇄/공유 버튼 선택적 제공

---

## TYPE-D: 입력형

**목적**: 사용자 데이터 입력
**대표 화면**: 정보 수정, 사진 등록, 성명변경 신청

### 레이아웃 원칙
- 라벨은 항상 인풋 위에 배치 (왼쪽 정렬 금지)
- 필수 항목: 빨간 asterisk (*) 표시
- 오류 메시지: 인풋 바로 아래, 빨간 텍스트
- 성공 메시지: 인풋 바로 아래, 초록 텍스트
- 하단: 저장/취소 버튼 (Primary/Secondary)

### PC 구조
```
[브레드크럼]
[페이지 제목]
[입력 폼 (1열 또는 2열 그리드)]
  [라벨 *] [인풋]
  [라벨 *] [인풋]
  [도움말 텍스트]
[저장] [취소]
```

### MO 구조
```
[페이지 제목]
[입력 폼 (1열)]
[버튼 (전체 너비)]
```

### 주의사항
- 자동완성(autocomplete) 속성 반드시 지정
- 실시간 유효성 검사 (blur 이벤트 기준)
- 비밀번호: 보기/숨기기 토글
- 파일 업로드: 허용 형식, 용량 안내 필수

### 주요 KRDS 컴포넌트
- Form Input, Select, Radio, Checkbox, File Upload, Button

## TYPE-E: 프로세스형 (Wizard)

**목적**: 단계별 진행, 완료까지 순서 안내
**대표 화면**: 원서 접수 단계 (시험장 선택 → 결제 → 완료)

### 레이아웃 원칙
- 최상단: 스텝 인디케이터 (현재 단계 강조)
- 스텝 인디케이터 하단: 현재 단계 제목
- 중단: 현재 단계 콘텐츠
- 하단: 이전/다음 버튼 (항상 고정 위치)

### PC 구조
```
[스텝 인디케이터: Step 1 > Step 2 > Step 3]
[현재 단계 제목]
[단계별 콘텐츠 영역]
[이전] [다음 / 완료]
```

### MO 구조
```
[스텝 인디케이터 (간략형: 1/3, 2/3)]
[현재 단계 제목]
[단계별 콘텐츠]
[하단 고정: 이전] [다음]
```

### 주의사항
- 중간 이탈 방지: "이탈 시 데이터 손실" 경고 모달
- 임시저장 기능 (세션 또는 로컬 저장)
- 이전 단계 수정 가능 여부 명시
- 완료 화면: 다음 행동 안내 (수험표 출력 등)
- 미결제 타이머: 30분 카운트다운 표시

### 주요 KRDS 컴포넌트
- Step Indicator, Button, Modal (이탈 경고), Toast (자동 저장 알림)

## TYPE-F: 안내형

**목적**: 정보/가이드 제공 (입력 없음)
**대표 화면**: 시험 안내, FAQ, 이용 약관, 개인정보 처리방침

### 레이아웃 원칙
- 좌측: 사이드 목차 네비게이션 (PC)
- 본문: 섹션별 콘텐츠, 앵커 링크 지원
- 정보 계층: H2 → H3 → 본문

### PC 구조
```
[브레드크럼]
[2단: 좌측 목차 | 우측 본문]
  [사이드 목차 - sticky]  [섹션별 콘텐츠]
[맨 위로 버튼]
```

### MO 구조
```
[드롭다운 목차 (선택)]
[본문 (단일 컬럼)]
[맨 위로 버튼]
```

### 주의사항
- FAQ: 아코디언 구조
- 표 데이터: 반응형 처리 (가로 스크롤 또는 카드 전환)
- 프린트 버전 고려

---

## TYPE-G: 관리형

**목적**: 관리자 운영 화면 (데이터 관리, 통계, 설정)
**대표 화면**: 시험 관리, 응시자 관리, 통계 대시보드

### 레이아웃 원칙
- 좌측: 관리자 GNB (사이드바)
- 상단: 페이지 제목 + 주요 액션 버튼
- 중단: 검색/필터 + 데이터 테이블
- 하단: 일괄 작업 + 페이지네이션

### PC 구조 (관리자 레이아웃)
```
[좌측 사이드바 - 관리 메뉴]  [우측 메인 영역]
                               [페이지 제목] [+ 추가] [내보내기]
                               [검색 + 필터]
                               [데이터 테이블 (정렬, 체크박스)]
                               [페이지네이션]
```

### MO 구조
- 관리형은 PC 전용 또는 제한적 MO 지원 명시

### 주요 KRDS 컴포넌트
- Table (정렬, 선택), Pagination, Button, Badge (상태), Modal (삭제 확인)
