# session-to-skill 사용 가이드

## 한 줄 요약

긴 대화에서 **실제로 성공하고 검증된 작업 절차**를 찾아 다른 Claude Code 세션에서도 재사용할 수 있는 `SKILL.md`로 바꿉니다.

## 언제 쓰면 좋은가

- 같은 작업을 다음 프로젝트에서도 반복할 예정일 때
- 시행착오와 복구 방법까지 대화에 남아 있을 때
- 팀원이 같은 품질 기준과 검증 순서를 따라야 할 때
- 세션이 길어져 핵심 절차를 별도 운영 자산으로 분리하고 싶을 때

## 언제 쓰지 않는가

- 한 번만 필요한 단순 답변
- 실행하지 않은 아이디어나 브레인스토밍
- 입력·산출물·완료 기준이 없는 대화
- 기존 스킬에 한 단락만 추가하면 해결되는 경우

## 호출 방법

Claude Code에서 자연어로 요청합니다.

```text
이 세션을 스킬로 만들어줘.
```

범위를 더 정확히 주려면:

```text
파일 정리 dry-run부터 manifest 검증까지의 부분만 session-to-skill로 정리해줘.
프로젝트 로컬 스킬로 만들고, 사용자 전역 폴더는 건드리지 마.
```

명시 호출이 필요한 경우:

```text
/session-to-skill 현재 세션의 검증·복구 워크플로우
```

## 예상 진행

1. 세션 범위와 증거를 읽습니다.
2. 트리거·입력·도구 순서·산출물·실패·검증을 추출합니다.
3. 새 스킬이 필요한지, 기존 스킬 보강이 나은지 판정합니다.
4. 등록 전 분석 결과를 확인합니다.
5. 승인된 경로에 `SKILL.md`를 만듭니다.
6. 구조 검사와 저위험 행동 smoke를 수행합니다.

## 결과 예시

```text
.claude/skills/my-repeatable-workflow/
  SKILL.md
  README.md
```

## 안전 원칙

- 대화의 토큰, 쿠키, OAuth 상태, 개인 메시지는 스킬로 옮기지 않습니다.
- 특정 사용자 경로와 고객명은 placeholder로 일반화합니다.
- 사용자 전역 `~/.claude/skills` 등록은 명시 승인할 때만 수행합니다.
- 실제 실행 검증 전에는 플러그인에 묶지 않습니다.

## 의존성

- 필수 외부 패키지 없음
- Claude Code의 project/user skill discovery 기능 사용
- `.skill` 압축은 전달용 선택사항이며 실행 원본은 `SKILL.md`입니다.

## 문제 해결

| 문제 | 확인할 것 |
|---|---|
| 스킬이 보이지 않음 | 디렉터리명과 frontmatter `name`, 설치 위치 확인 |
| 엉뚱한 세션을 분석함 | 요청에 분석 범위 또는 transcript 경로 명시 |
| 결과가 너무 일반적임 | 실제 도구 출력·수정 요청·검증 로그가 세션에 있는지 확인 |
| 개인정보가 남음 | 배포 전 저장소 validator와 수동 diff 검사 재실행 |
