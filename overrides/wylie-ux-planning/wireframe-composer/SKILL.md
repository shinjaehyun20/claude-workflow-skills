# Wireframe Composer

## 입력 우선순위

1. `screen-requirements.md`
2. 요구사항·RFP와 업무 흐름
3. `krds-compliance-report.md`
4. 벤치마킹 시사점

화면 목록과 요구사항 추적 근거가 없으면 먼저 입력을 보강한다.

## Workflow

1. **화면 목록 잠금**: 화면 ID, 화면명, 채널, 요구사항, 우선순위를 확정한다.
2. **유형 분류**: 대시보드·목록·상세·입력·프로세스·안내·관리형으로 분류한다. 세부 기준은 `references/screen-type-guide.md`를 사용한다.
3. **공통 구조 정의**: 그리드, 헤더, 내비게이션, 푸터, 공통 컴포넌트를 먼저 정한다.
4. **화면 구성**: 필수 UI, 상태, 예외, 오류, 로딩, 빈 상태를 포함한다.
5. **흐름 연결**: 트리거, 대상 화면, 조건, 실패 처리를 표로 만든다.
6. **검증**: 요구사항 커버리지, 화면 ID 중복, 접근성, 반응형, 누락 상태를 확인한다.

## 공공 서비스

`references/krds-checklist.md`를 사용한다. KRDS 적용 여부, KWCAG 기준, 컴포넌트 선택 근거를 주석이나 화면 설명에 기록한다.

## 산출물

사용자가 지정한 출력 루트 또는 `output/wireframes/`에 저장한다.

- `screen-list.md`
- `interaction-map.md`
- 화면별 HTML 또는 이미지 와이어프레임
- 요청 시 화면설계서 PPTX

HTML은 실제 대표 문구, 시맨틱 구조, label/alt/aria, 키보드 접근을 포함한다. PPTX는 1화면 1슬라이드를 기본으로 하되 승인된 템플릿이 있으면 그 구조를 우선한다.

## 환경 적응

- HTML 생성 도구가 있으면 반응형 프로토타입을 만든다.
- PPTX 도구가 없으면 화면 목록·레이아웃 명세·HTML을 먼저 제공하고 미생성 항목을 명시한다.
- 프로젝트 검색 도구가 없으면 사용자가 제공한 파일과 현재 작업 폴더만 읽는다.
- 특정 OS 경로나 특정 에이전트가 없어도 동작해야 한다.

## 다음 단계

Figma 시안이나 디자인 결과가 나오면 `design-spec-review`로 화면설계서와 정합성을 검수한다.

## 완료 조건

- 화면 ID와 요구사항 추적이 1:1 또는 근거 있는 N:1로 연결됨
- 모든 화면에 기본·오류·빈 상태 검토됨
- 인터랙션 이동 대상이 존재함
- PC/MO 차이가 명시됨
- 렌더 또는 브라우저 검증 통과
