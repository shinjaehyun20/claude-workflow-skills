# Public Portal Benchmark

## 입력

- 분석할 서비스 유형과 사용자 과업
- RFP, 요구사항, AS-IS 진단 등 프로젝트 근거
- 국내·해외 포함 범위와 집중 관점

## 절차

1. 프로젝트의 문제, 목표, 제약, 평가 기준을 먼저 추출한다.
2. `references/benchmark-targets.md`를 시작점으로 국내 3개·해외 2개 이상 후보를 고른다.
3. 사용 가능한 웹 검색·브라우저·스크린샷 도구로 현재 화면을 확인한다. 접근 불가 항목은 추정하지 않는다.
4. IA, 핵심 태스크 단계, 디자인 시스템, 반응형, 접근성, 피드백, 성능 안내를 같은 기준으로 기록한다.
5. 현행 서비스를 첫 열에 둔 비교 매트릭스를 만든다.
6. 각 시사점을 AS-IS 문제 또는 요구사항 ID와 연결한다.

## 근거 규칙

- 사이트명과 확인 URL, 확인일을 기록한다.
- 검색 스니펫만 본 경우 `스니펫 근거`라고 표시한다.
- 로그인·지역 제한·차단으로 확인하지 못한 항목은 `미확인`으로 둔다.
- 좋은 사례 나열만 하지 말고 적용 이유와 제약을 함께 쓴다.

## 산출물

`benchmark-report.md`:

1. 목적과 범위
2. 프로젝트 개선 키워드
3. 대상과 선정 이유
4. 대상별 근거
5. 비교 매트릭스
6. 적용 시사점과 우선순위
7. 다음 단계 입력 패키지

## 다음 단계

결과를 `asis-tobe-analysis`에 전달해 문제→개선→화면요건으로 구체화한다. 개선 근거가 이미 충분하면 `wireframe-composer`로 바로 넘길 수 있다.

## 완료 조건

- 국내 3개·해외 2개 이상 확인 또는 부족 사유 명시
- 모든 핵심 사실에 URL·확인일 있음
- 시사점 3개 이상이 요구사항 또는 AS-IS 문제와 연결됨
