# Proposal Review

## 입력

- 제안서 PDF/PPTX/DOCX
- 가능하면 RFP, 평가표, 제출 형식, 마감 정보
- 검토 목적과 수정 가능 범위

## 절차

1. 파일을 읽기 전용으로 열어 페이지/슬라이드 수, 사업명, 제출 형식, 버전을 기록한다.
2. 렌더하여 글자 깨짐, 플레이스홀더, 잘림, 누락 이미지를 확인한다.
3. RFP 평가표가 있으면 배점 항목과 제안서 목차를 매핑한다. 없으면 추정값임을 명시한다.
4. 심사위원의 빠른 읽기 순서로 표지·목차·사업 이해·방법론·인력·실적·일정·가격을 검토한다.
5. 다음 위험을 점검한다.
   - 필수 인력·역할·투입률 누락
   - 모호한 약속과 미완성 수치
   - 제출 형식·날인·마감 오류
   - 근거 없는 수치와 출처 누락
   - 유사 실적·성과·KPI 부족
   - 경쟁사가 복제하기 어려운 차별화 부족
6. 제안서가 답하지 못하는 예상 질문 5개를 만든다.
7. 영향도와 수정비용을 고려해 우선순위를 정한다.

## 도메인 보강

- 공공: KWCAG/KRDS, 정보취약계층, 법·계약·하자보수, 이해관계자 참여
- 금융: 보안·망분리·접근성·규제·감사·운영 안정성
- 민간: ROI, 전환율, 리텐션, 측정 체계, 실행 속도

## 출력

1. 총평과 신뢰 수준
2. 배점 매핑과 예상 점수 범위
3. 탈락/감점 위험
4. 잘 된 부분
5. 차별화 후보와 증명 근거
6. 예상 질문 5개
7. 수정 우선순위 표

모든 비판에는 페이지/슬라이드 번호와 근거 문구를 붙인다. 확인하지 못한 사항은 사실처럼 단정하지 않는다.

## 완료 조건

- 기술력·사업이해·수행방법·실적·가격 축을 모두 검토함
- 수정 우선순위 Top 3가 구체적임
- 차별화 후보가 실제 증거와 연결됨
- 개인 경로·내부 메시지·비밀값을 리포트에 포함하지 않음
